# 南京市内智能行程表

Windows个人行程规划软件，暖色月历、列表和周课表界面。采用C#、WPF、SQLite；手工填表断网可用，智能填表和新路线查询按需联网。

## 运行

解压整个运行包，双击 `NanjingPlanner.exe`。请放在自己有写入权限的普通文件夹中，不要直接从压缩包内启动。运行包包含.NET运行组件，无须另装.NET SDK。

地图使用Microsoft Edge WebView2运行时；机器未安装时会显示提示，其他功能仍可使用。仅支持64位Windows桌面。数据默认保存在程序旁的 `Data` 文件夹；备份时关闭软件并复制整个Data。分享软件时请勿附上自己的Data。

## 基本操作

1. 左侧新建或设置“工作安排”“个人安排”等行程表。“显示”只控制卡片可见性；“生效”控制是否参与排程和冲突检查。
2. “添加行程”录入事项、日期、时间和可选地点。选择“每周重复”并勾选多个星期，各天共用开始时间与时长，结束日期可留空。
3. 默认“月历”显示整月，点击卡片编辑，点击日期选择当天，日期旁“＋”添加；顶部可切换月份、今天或点击月份跳转。卡片内容随行高增长，向下滚动查看；窄窗口可横向滚动，星期表头同步。月历拖动改日期时保留原时间与时长，修改前确认。
4. “列表”按日期分组，支持编辑、删除和完成标记；完成仅改变显示，不取消安排或冲突。初始当前月，可逐月追加，最多连续6个月；使用顶部月份切换继续查看。短间隔包含交通时间，不代表扣除交通后的剩余时间。
5. “周课表”保留原时间轴：双击卡片编辑，拖动修改日期或时间，拖动上下边缘修改时长，按15分钟对齐。重叠活动并列显示。跨日事项可勾选“结束于次日”，月历与列表显示跨日续段。
6. 周期事项默认只改当前一次；选择“从所选日期起调整整套规则”会保留历史并处理未来单日例外。删除默认只取消当前一次。
7. 时间重叠或路线尚待核验会保留提示，用户可以确认保存软冲突；结束早于开始等非法数据不能保存。

## 本次整合范围

本分支只更换中央看板；左侧行程表、右侧原辅助填表与详情、地图等保持原有功能。原 Python 程序未修改，双方数据库不混合。AI 对话未来按合作方方案单独整合，本包保留稳定1.0的原辅助填表方式，未包含此前未交付的会话实验。

看板视图与完成标记保存在 `Data/board.json`。复制自己的 Data 前请关闭两边软件并完整备份；不要用新目录的空数据覆盖原数据。本运行包不会自动搬移旧版本数据。

## 智能辅助填表

在“服务设置”填写兼容Chat Completions的HTTPS接口地址、模型名称、API密钥。接口地址可填到`/v1`或完整`/chat/completions`；本机模型可用localhost HTTP。不支持JSON响应模式的接口可关闭该选项。保存设置不发起请求。

勾选允许读取的行程表与日期，再输入需求，如“11月2日14点到15点在南京图书馆读书”。只发送授权表的名称、生效信息及范围内的必要事项，默认不发送备注；其他生效表只在本地检查冲突。停用表仍可显示和编辑，但不会成为生效约束。生成后逐项核对新增、修改、删除，勾选并确认后才写入数据库。允许修改未来周期须单独勾选授权，预览会显示真实影响起日、星期、结束日和例外处理。

“南京一日游”等开放请求先获得活动方向，再补充日期、时长和具体选择。助手不代替地点、票价和交通数据核验。取消请求、网络失败、无效或过期草稿均不覆盖原行程。

## 地图与当天路线

服务设置中的高德Web服务Key用于行政区域、地点搜索和路径规划；Web端JS Key及securityJsCode用于内嵌地图。请在自己的高德开放平台应用中配置相应服务权限、配额和JS使用设置。项目不附带公共Key。

1. 选择日期，搜索并选择准确的南京市内出发点，填写最早出发时间。
2. 勾选允许的步行、骑行、公交、地铁、自驾、打车方式，可混合。选择自驾或自有自行车表示车辆初始位于出发点。自驾停车缓冲由用户估算。
3. 未确认地点会先列出真实搜索结果，请逐项选择。行政区及路线几何检查排除市外路线，火车、城际和飞机不在范围内。
4. 生成方案比较交通时间、已知费用、未知项及步行量；可预览地图、更换某一段交通，再统一复核衔接。固定事项保留原时间；仅勾选重排时，才移动当前表内没有单日覆盖例外的灵活事项。
5. 确认方案才保存路线和活动时间；相关活动、地点或生效表变化后，路线需要重新核验。

交通时间为查询参考，非实时监测或未来到达保证。公交/地铁包含必要的接驳步行，“步行”选项控制是否允许另选全程步行。道路拥堵仅显示接口实际返回内容，车厢、景点等人流拥挤程度暂无数据。自驾已知费用可能仅包含通行费，油费及停车费未知；打车参考价、共享单车可用性和费用按接口能力显示，未知不当作零。已确认费用快照会随路线保存，重启后仍可查看。

自动候选采用有限搜索，最多12项当天事项、100次路线查询，并保留最多3个不同方向的方案；不保证穷举或全局最优。自动规划暂不处理跨日事项，请手动安排跨日部分。某方式接口不可用会说明原因并尝试保留其余候选。没有可行结果可尝试提前出发、放宽灵活时间窗或增选交通方式。

## 提醒与数据

提醒仅在软件运行时检查，约20秒一次。有有效路线时按出发时间提醒，否则回退到活动开始；每个实例去重。启动时仅汇总当天已经错过的提醒，不声称关机或退出后仍能通知。时间均按北京时间。

API密钥用当前Windows用户的系统保护保存。数据库没有明文API密钥。复制到其他用户或重装系统后可能需要重新配置。所有本地行程仍是普通SQLite文件，应保管好自己的Data目录。

## 工程与验证

`Planner.Core`负责周期、冲突、草稿、排程和提醒；`Planner.Data`负责SQLite、密钥、LLM和高德；`Planner.Desktop`负责WPF及WebView2；`Planner.Tests`为独立行为检查程序。测试夹具不作为真实交通数据展示。

使用.NET SDK 10.0.201，可打开 `NanjingPlanner.sln`；在desktop-wpf目录执行 `./build.ps1` 可还原依赖、运行行为测试并生成Windows发布目录。课程设计原报告保留，当前开发结果与边界以本说明和验证记录为准。旧版测试数据库会自动从结构1升级为结构2，保留行程；升级前建议关闭软件并备份Data。

未提供外部服务凭据，本次不能验证真实LLM模型兼容性、高德账号权限/费用/配额、在线地图加载和真实路线准确性。这些需要在服务配置后联调；软件不会用模拟路线替代在线结果。


看板行为检查：构建并执行 `Planner.Tests`；实际 WPF 检查可运行 `Planner.BoardChecks`，必须传入一个新的隔离目录（其中会写测试数据库和示例截图）。例如：

```powershell
dotnet run --project Planner.BoardChecks -c Release -- "C:/Temp/TripBoardCheckNew"
```

截图包含“示例”测试数据，未连接真实在线服务。构建脚本可通过 `-OutputDirectory` 指定独立发布目录、`-PackageDirectory` 指定已有依赖缓存。
